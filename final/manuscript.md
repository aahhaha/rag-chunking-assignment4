# Chunking and Context Limits in Retrieval Augmented Question Answering with Compact Models
Aibyn Samat
Astana IT University, Astana, Kazakhstan
Correspondence: 242187@astanait.edu.kz

## Abstract
Document chunking determines which text a retrieval augmented generation system can find and use. Semantic boundaries may preserve meaning, but the passages they produce can exceed model input limits. This study compares fixed, overlapping and semantic chunks on the same 500 SQuAD development questions. The pipeline uses normalised MiniLM embeddings, exact FAISS search and greedy FLAN T5 base generation. Retrieval returns five chunks; the generator receives the first three. Exact McNemar tests with Holm correction compare binary outcomes, while 2,000 paired question bootstrap samples estimate uncertainty. Recall at five is 75.2% for fixed chunks, 81.8% for overlap and 66.4% for semantic chunks. Overlap gains 6.6 percentage points over fixed, with a paired 95% interval of 3.0 to 10.0 points and adjusted p = 0.0008. Exact Match is 54.8%, 58.0% and 1.4%, respectively. The overlap advantage in exact answers is not statistically established. Semantic prompts are truncated for 95.6% of questions. After an exploratory context cap, semantic Exact Match rises from 1.33% to 24.67% on the same 300 questions. The results favour overlap for retrieval in this compact pipeline. They also show why a passage containing an answer may still provide unusable model input. The semantic failure involves both chunk length and boundaries, so it does not establish that semantic segmentation is generally inferior.

Keywords: evidence selection; passage segmentation; SQuAD; input truncation; paired evaluation

## 1 Introduction
Retrieval augmented generation connects a language model to a searchable collection of external text. The original RAG formulation combines parametric knowledge with retrieved passages to support knowledge intensive tasks {rag}. Dense passage retrieval provides an efficient route to candidate evidence {dpr}. A practical implementation must also decide the unit of retrieval. Whole articles usually contain too much unrelated material, whereas very short fragments may omit the sentence that explains an answer. Document segmentation therefore affects the information represented in the index before a user asks a question.

This study examines chunking in a small pipeline built from public encyclopedic text and models that can run locally. Such a setup is useful for student projects and applications with limited computing resources. It also makes input limits hard to ignore. A passage may read as a complete explanation yet be too long for the model that embeds it. Combining several retrieved passages can then exceed the answer generator's limit as well. Finding the answer somewhere in the original text is therefore only one step: the relevant words and the question must also survive when the system constructs the model input.

Sentence embedding models convert texts into vectors that can be compared {sbert}. SQuAD provides questions with reference answer spans in Wikipedia passages {squad}. Together, they allow two separate checks: whether retrieval finds an answer string, and whether the generator returns a matching answer. Neither check is perfect. A short answer string can appear without the sentence needed to understand it. However, both scores can be calculated directly from saved outputs, without asking another language model to judge them. This makes it easier to inspect what went wrong when a method performs poorly.

The experiment compares fixed character windows, overlapping windows and semantic boundaries based on changes in sentence embeddings. Fixed windows are a straightforward baseline. Overlap repeats text near a boundary, which may keep an answer and its explanation together. Semantic segmentation tries to group related sentences, although the resulting passages can vary greatly in length. Previous studies give different reasons to test these options. Qu and colleagues found no consistent advantage for semantic segmentation across their retrieval tasks {qu}. Kiss and colleagues reported gains with a different Max Min algorithm {kiss}. Their results suggest that the choice needs to be tested within the system that will use it.

The position and amount of context also matter. Liu and colleagues showed that models use information differently depending on where it appears in a long input {lost}. Their work examines information that remains in the input; this pipeline can also lose text through truncation. RAG evaluation frameworks distinguish context relevance, answer relevance and faithfulness {ragas}. These are separate questions about the system. A retriever may find a passage containing the answer while the generator receives an incomplete version of that passage. For this reason, the experiment reports retrieval and answer scores separately.

The research question is how fixed, overlapping and semantic segmentation change context availability and answer accuracy under the same compact model configuration. The original hypothesis predicts that semantic segmentation improves both Recall at five and Exact Match over fixed segmentation after correction for multiple comparisons. The study retains that joint rule even though its results favour other configurations. It treats the subsequent context cap and answer position checks as exploratory analyses, because they were added after a length problem became visible.

This study makes three contributions. It compares the methods on the same question IDs with a shared retriever, generator and scoring procedure, and releases the outputs for each question. It then examines the unusually low semantic answer score through truncation records and a context cap tested on matched questions. Finally, it documents a full technical rerun and distinguishes that check from independent human replication. The study evaluates existing splitters; it does not introduce a new algorithm. Its purpose is to show what these methods do in a reproducible local setup and to explain where the model input limits complicate the comparison.

## 2 Related Work
### 2.1 Retrieval representations and benchmark scope
Dense retrieval encodes questions and passages separately and ranks passages by vector similarity. The encoder and the way passages are defined both affect this ranking. MTEB evaluates embeddings across several tasks, including retrieval, rather than treating sentence similarity as sufficient evidence of retrieval quality {mteb}. Here, the encoder stays the same while the passages change. This keeps the comparison manageable, but also sets its scope: the scores show how the splitters work with this encoder. Another encoder could represent the same passages differently and change the ranking of the three methods.

BEIR evaluates retrieval across different domains and shows why a single dataset gives a limited view of performance {beir}. Wikipedia questions do not test the same demands as legal documents, academic theses or multilingual search. The collection used here is small and public, which makes it possible to inspect the saved questions behind each score. The cost of that choice is limited coverage. Fixed windows serve as the baseline in this experiment, but the study does not compare them against the strongest systems in a broad retrieval benchmark. Results from those benchmarks provide context rather than directly comparable scores.

Knowledge intensive benchmarks distinguish downstream task performance from supporting provenance. KILT explicitly evaluates both within a shared knowledge source {kilt}. Our hit indicator is simpler: it checks answer string containment in a fragment from the correct article. It does not identify every relevant passage or verify an entailment relation. The difference matters when comparing results with conventional information retrieval metrics. We retain the familiar Recall at k label but state its binary operational definition throughout the manuscript.

### 2.2 Segmentation and pipeline interaction
Qu and colleagues provide the closest comparison: they test semantic and fixed segmentation for document retrieval, evidence retrieval and answer generation {qu}. Semantic segmentation does not give consistent gains across their tasks. The present experiment uses a smaller setup with character windows and compact local models. It focuses on what happens when the resulting passages meet the encoder and generator input limits. It does not repeat their full benchmark or compare computation costs. The additional evidence here comes from the recorded truncation and from checking whether a shorter context changes answers on the same questions.

Kiss and colleagues use semantic similarity to form consecutive sentence groups in their Max Min method {kiss}. They evaluate clustering and multiple choice RAG, whereas this study uses percentile breakpoints and scores generated answer spans. These differences make the results difficult to compare directly. A poor score for the percentile splitter in this pipeline does not establish that Max Min would fail under its own evaluation conditions. Table 1 sets out the methods and tasks in the closest studies so that the shared label semantic chunking does not hide those differences.

[[RELATED]]

Several recent papers in the proposed primary journal examine other choices within RAG pipelines. Upadhyay and Viviani combine topical relevance and factual accuracy for health information retrieval {health}. Elkiran and Rasheed compare retriever and reranker combinations using retrieval, generation and efficiency measures {pairings}. These papers show the journal's interest in evaluating the parts of a RAG system together. Their numerical results are not baselines for this experiment, which includes neither health misinformation evaluation nor reranking. The original run also lacks the timings needed to make the same kind of efficiency comparison.

Chen compares similarity measures for Chinese RAG across more than one dataset and encoder, using paired statistical evaluation {chinese}. That broader setup contrasts with the single English collection used here. Ghaywat and colleagues survey conversational RAG and discuss how its stages work together {survey}. Muthusami and Saritha combine retrieval with structured reasoning in an educational application {hybrid}. These recent articles establish the topical fit of the backup journal. They also help place the study among other RAG evaluations, although their tasks and architectures differ too much for a direct comparison of scores.

### 2.3 Retrieved evidence and generated answers
Different RAG architectures combine retrieved evidence in different ways. Fusion in Decoder processes multiple passages within an architecture designed to combine them {fid}. REPLUG uses a tunable retriever with a frozen black box model {replug}. Self RAG adds adaptive retrieval and reflection during generation {selfrag}. These systems change how a model selects or uses external information. The pipeline examined here is simpler: it retrieves a fixed number of chunks and concatenates three of them in a prompt. Its results are therefore most relevant to that arrangement. They do not show how the same splitters would perform in each of these other architectures.

T5 treats language tasks as text to text problems {t5}, and instruction tuning improves how released FLAN models follow task instructions {flan}. FLAN T5 base is small enough for local execution, which is useful for this course project. Its input budget is also much smaller than that of many newer models. The experiment uses the same generator without retraining it for each splitter. This holds one major part of the system constant, but leaves an open question: could a generator adapted to longer or differently structured passages use the semantic chunks more successfully? The current outputs cannot answer that question.

Long context research distinguishes nominal window size from effective use. LongBench evaluates several long text tasks rather than relying on one question answering dataset {longbench}. Shi and colleagues show that irrelevant information can distract language models {distraction}. Together with positional effects {lost}, these studies caution against assuming that supplying more characters necessarily improves answers. Our recorded truncation is an additional, mechanically observable problem. We do not claim that positional sensitivity or distraction caused each error in our outputs.

### 2.4 Evaluation and the remaining gap
Surface matching offers a reproducible answer score, but it does not establish factual support. ARES evaluates context relevance, answer faithfulness and answer relevance using trained judges with human annotation support {ares}. ALCE evaluates the quality of evidence citations in generated text {alce}. These dimensions motivate future validation beyond EM and token F1. They were not measured here, and no unrecorded faithfulness score is inferred from answer matching.

HyDE changes the query representation by generating a hypothetical document before retrieval {hyde}. This experiment keeps the query representation fixed so that the comparison stays focused on chunking. Adding query expansion, reranking or an adaptive retriever would require another experiment to distinguish their effects. The question addressed here is narrower: how do three existing splitters behave in the same compact pipeline, and what do the length diagnostics tell us about their differences? This extends previous comparisons with a documented local case. It does not assume that chunking comparisons themselves are new.

## 3 Materials and Methods
### 3.1 Design and provenance
Each question is evaluated with all three segmentation methods. This paired design allows the analysis to compare outcomes for the same questions rather than compare unrelated averages. The measured outcomes are retrieval hits, Exact Match, token F1, prompt truncation and retrieved character volume. Segmentation is the factor being changed. The collection, question IDs, normalisation, encoder, search index type, retrieval depth, prompt format and decoding settings stay the same. Chunk length and index size change with the splitter. Although the nominal model limits are shared, the models may consequently process different proportions of the retrieved text.

The research question began in the earlier course assignments. Assignment 3 produced the main and context budget outputs, and Assignment 4 developed their analysis. With the instructor's permission, the final manuscript brings those experiments together instead of presenting them as new runs. The settings record was written retrospectively; there was no uploaded protocol before the experiment. Recall at five became the primary reporting measure after the results were available. The original hypothesis is retained: semantic segmentation must improve both Recall at five and EM. Keeping that requirement avoids changing the hypothesis simply because another method scored better.

### 3.2 Dataset and sample
SQuAD version 1.1 development data contain 10,570 questions across 48 Wikipedia articles. Source paragraphs are joined within each article with two newline characters. All articles form the retrieval collection. A Python pseudorandom shuffle with seed 42 selects the first 500 questions. Every selected question has one or more reference answers, and all are retained. This is open retrieval within the development article collection, rather than the original reading comprehension setting that supplies a question's gold paragraph directly.

The exploratory budget run uses the first 300 questions of that same shuffled list. It is a subset, not a held out validation set. The pilot contains 100 questions and is reported separately. Saved question IDs allow exact alignment across methods and runs. The analysis asserts that all three methods contain the same IDs and that the budget IDs match the first 300 main IDs. SHA 256 hashes identify the source dataset, result files and experiment script. No new annotated dataset or model training split is created.

### 3.3 Segmentation and retrieval
Fixed segmentation uses LangChain CharacterTextSplitter with an empty separator, a 500 character chunk size and zero overlap. The overlap condition uses the same implementation and size with 50 overlapping characters. Semantic segmentation uses LangChain SemanticChunker with a percentile breakpoint threshold of 95. It compares sentence representations and splits at sufficiently large semantic changes. No maximum token cap is imposed on its output. The threshold is not a confidence probability or a target answer accuracy.

The encoder is sentence transformers all MiniLM L6 v2. Document and question embeddings are normalised. FAISS provides exact flat nearest neighbour search {faiss}. Five chunks are retrieved for each question. With unit vectors, squared Euclidean distance and cosine similarity induce the same ordering, apart from numerical ties. The experiment does not use an approximate index, a reranker or a learned query expansion stage. The maximum embedding sequence length is 256 tokens, with approximately 254 positions available for ordinary text after special tokens. Longer strings can be truncated during representation.

### 3.4 Generation and context intervention
The generator is google flan t5 base in evaluation mode. It receives the first three retrieved chunks concatenated with newline separators. The prompt requests an answer using only that context and places the question after it. Tokenisation uses truncation with a maximum input length of 512 tokens. Greedy decoding disables sampling and permits at most 32 new tokens. These settings are identical across segmentation conditions. They make the saved run deterministic in the observed environment, while not guaranteeing identical results under every software or hardware revision.

The additional run keeps only the first 1,500 characters of the concatenated context before constructing and tokenising the prompt. It uses the same index and retrieved passages. This cap was added after the prompt length problem was noticed, so it is an exploratory check. A shorter context can leave room for the question, but it also removes part of the retrieved text. Both changes can affect the answer. The check therefore examines prompt construction as a whole. The truncation flag records whether the resulting prompt exceeds the tokenizer limit; it does not identify the exact words lost for each question.

### 3.5 Metrics
A hit at k equals one when at least one of the first k chunks belongs to the question's article and contains a nonempty normalised reference answer string. Otherwise it equals zero. Recall at k is the mean of this indicator across questions, for k equal to one, three and five. This is answer string hit rate, not exhaustive recall over all relevant passages. It may accept an irrelevant occurrence of a short answer and does not establish that the generator receives the complete supporting statement.

Answer normalisation lowercases text, removes punctuation and English articles, and collapses whitespace. EM is one when the normalised prediction equals at least one normalised reference. Token F1 uses multiset word overlap to compute precision and recall, then their harmonic mean. For questions with multiple references, the best score is retained separately for EM and F1. Final answer scores average the per question values. Thus an acceptable shorter span may obtain zero EM and positive F1. The analysis does not use semantic similarity or an LLM judge to replace these definitions.

### 3.6 Statistical analysis
The analysis estimates uncertainty by drawing 2,000 samples of question rows with replacement, using bootstrap seed zero. The 2.5th and 97.5th percentiles give the 95% interval {efron}. When estimating a difference, it draws the same question IDs for both methods, preserving the pairing. The models are not run again during this procedure. The intervals describe variation across the sampled questions under this fixed pipeline. Questions from one article may share information or difficulty, so treating every question as independent can understate uncertainty across documents. An article cluster bootstrap would address a different level of variation.

Binary Recall at five and EM outcomes are compared using exact two sided McNemar tests {mcnemar}. If b is the number of questions only method B answers successfully and a is the number only method A answers successfully, the test conditions on a plus b and evaluates a binomial null probability of one half. Holm adjustment controls multiple testing separately within the three Recall comparisons and within the three EM comparisons {holm}. The significance threshold is 0.05. F1 differences use paired bootstrap intervals because F1 is not binary. A nonsignificant result does not establish equivalence.

### 3.7 Error analysis ethics and reproducibility
All EM failures are grouped by the first matching rule: truncated prompt, no hit among five, hit only at ranks four or five, hit among three with F1 at least 0.5, hit among three with positive F1 below 0.5, or hit among three with zero F1. This priority prevents double counting. A separate qualitative review examines the first 30 fixed failures in saved order. AI assisted the labels, and the student reported checking them. No independent inter rater agreement is claimed.

The experiment uses a public benchmark and involves no recruited participants or newly collected personal records. The repository identifies the licences for the original analysis, dataset and models separately. A full inference rerun on 27 October 2026 used cached models in the existing local environment. Another check installed the analysis dependencies in a clean environment and recalculated the saved outputs. These checks establish different things: the first checks repeatability of model predictions in that environment, while the second checks the analysis installation. Neither is described as an independent human replication, since Codex operated the technical rerun on the student's computer.

### 4.2 Paired comparisons
Table 5 reports all six binary comparisons. For Recall at five, overlap succeeds alone on 58 questions and fixed succeeds alone on 25. The net gain is 33 questions, or 6.6 percentage points. Its paired bootstrap interval is 3.0 to 10.0 points, and its exact raw p value is approximately 0.000378. The Holm adjusted value is approximately 0.000757, reported as 0.0008. Both other retrieval comparisons favour the nonsemantic condition after adjustment. Semantic is 8.8 points below fixed and 15.4 points below overlap.

The answer scores give a less clear result for overlap versus fixed. EM is 3.2 points higher, but its paired interval runs from minus 1.0 to plus 7.0 points and the exact p value is 0.1332. At the chosen threshold, the data are insufficient to establish an advantage. They also do not establish that the methods are equivalent. Semantic EM is much lower than both alternatives. Table 6 gives the F1 comparisons: overlap is 3.06 points above fixed, again with an interval that includes zero, while semantic is well below the other methods.

### 4.5 Hypothesis and technical reproduction
The original semantic superiority hypothesis is not supported: semantic falls below fixed on both required outcomes. This conclusion refers to the tested percentile splitter and pipeline. On the later technical rerun, all 1,500 prediction strings and per item numeric metrics match the historical main outputs. Total elapsed time is 3,887.93 seconds. A clean saved output analysis also reproduces the main summary byte for byte, and six main McNemar values agree with SciPy. These checks establish technical consistency of the supplied evidence, while external human reproduction remains unperformed.

## 5 Discussion
### 5.1 Interpretation and comparison with prior work
Overlap improves the retrieval hit rate in this compact configuration. Repeating a short region can preserve answer text split by a fixed boundary, but it also changes representations and neighbour rankings. The saved CSVs do not retain ranked chunk IDs, so the 33 additional hits cannot all be attributed to repaired boundaries. The strongest supported conclusion is the paired improvement under the specified implementation. It remains possible that a token based or sentence aware baseline would behave differently.

The difference between retrieval and answer scores is understandable once the two stages are separated. Recall at five checks five passages, but the generator receives only three. Even in those three, a hit only confirms that the original text contains an answer string before tokenisation. Useful text or the question may later be removed. The generator can also select a nearby wrong entity or return only part of the expected span. These possibilities explain why a retrieval gain needs a separate answer evaluation. The EM and F1 intervals do not establish the same advantage that the Recall interval does.

The weak semantic result is consistent with Qu and colleagues' finding that semantic gains are unreliable across tasks {qu}, although this experiment covers a smaller setting. Max Min uses a different rule, different models and different evaluation tasks {kiss}; the present result cannot be used to reject that method. The recent studies in the target journal examine other pipeline choices, including relevance signals and reranking {health}{pairings}. This study adds a specific case in which passage length conflicts with model input limits. It does not transfer numerical conclusions from those systems or measure the computational cost of semantic chunking.

The context cap provides further evidence that prompt construction mattered. Semantic answers improve on the same 300 questions without changing the retriever. However, the cap affects both the available evidence and whether the question fits into the input. The improvement cannot be assigned to only one of these changes. It also does not show that 1,500 characters is the best budget: that setting was examined after the original problem was visible. A follow up should choose the policy in advance and test it on new questions. That would show whether the improvement survives beyond the questions used to diagnose the failure.

### 5.2 Practical implications
For a similar English Wikipedia application with these compact models, fixed windows with a small overlap are a sensible first configuration to test. The result still needs to be checked on the application's own questions. More broadly, the experiment suggests checking token counts before indexing and reserving space for the question when building a prompt. Saving the actual text given to each model would make later failures easier to inspect. Looking only at the original retrieved chunk can be misleading: it may contain the answer even though the encoder or generator processed a shorter version.

A larger input window would remove some hard truncation, but other context problems would remain. LongBench and the positional studies show that the amount and location of information affect model use {longbench}{lost}. A passage can fit into the input and still be irrelevant or poorly used. When an application needs supported explanations, faithfulness and citation evaluation should supplement answer matching {ares}{alce}. Those measures were not collected here. Neither were the timings needed to compare latency or cost across methods. The number of chunks and retrieved characters describes the input, but cannot substitute for measured runtime or memory use.

### 5.3 Threats to validity
The most important limitation is that the methods change both chunk boundaries and effective input length. Semantic uses one setting and produces much longer passages, so its score does not isolate the benefit of grouping sentences by meaning. The question also appears at the end of the prompt, where truncation can remove it. Separate token caps and parameter tuning might produce a better deployment configuration, but that would test a different setup. The present result describes these existing splitters inside one fixed pipeline. It should be read as a failure of that combination, rather than as a general measure of semantic coherence.

The metrics impose further limits. A short reference string can appear in an irrelevant passage, while EM can reject a reasonable answer phrased differently. The small manual review illustrates these problems but cannot estimate how often they occur overall. The statistical analysis also treats related questions from the same 48 articles as individual resampling units. Intervals could be wider if articles were resampled instead. Holm correction is applied separately to the three retrieval comparisons and the three EM comparisons. It does not adjust every exploratory check as one combined family. These choices should be considered when interpreting the strength of the evidence.

The experiment covers one English dataset, one encoder, one generator and one shuffled selection of questions. Its ranking may change with another collection or model pair. Benchmark text may also have appeared during model pretraining, so a correct answer does not prove that the model relied entirely on retrieval. Greedy decoding keeps sampling disabled but does not remove uncertainty about question selection. Finally, the rerun used cached models and an existing environment. It checks technical repeatability, without providing an independent review of the qualitative labels. The instructor accepted this arrangement for the course; independent scientific replication remains a separate step.

### 5.4 Follow up study
A follow up should decide the protocol before examining new questions. It could compare semantic chunks with and without token caps, preserve the question in every prompt, and match retrieval depth to the generation budget. Additional datasets and encoders would show how much the ranking depends on this model pair. Useful controls include a strong lexical retriever, generation without retrieval, and generation from the gold passage. Resampling articles and asking another person to rerun the experiment would strengthen the checks. Saving ranked chunk IDs, token counts, full prompts, model revisions and stage timings would also help locate the remaining failures more precisely.

## 6 Conclusion
This study compared fixed, overlapping and percentile semantic segmentation in a compact RAG pipeline on the same 500 SQuAD questions. Overlap achieved Recall at five of 81.8%, compared with 75.2% for fixed and 66.4% for semantic. Its 6.6 percentage point retrieval advantage over fixed remained significant after Holm correction. The observed EM increase from 54.8% to 58.0% was not statistically established. The original hypothesis that semantic segmentation improves both retrieval and exact answers was not supported in this configuration.

Finding an answer string and giving a model usable evidence turned out to be different steps. Semantic prompts were truncated on 95.6% of questions and produced 1.4% EM. On the same 300 questions, limiting context increased semantic EM from 1.33% to 24.67%. This improvement shows that context construction affected the answers in this setup. Because the cap changed both retained text and space for the question, the check does not isolate the effect of semantic boundaries. It was also chosen after the problem was observed and needs testing on unseen questions.

The study provides saved outputs for a paired comparison, a matched context cap check and a record of technical reproduction. Its practical lesson is to test chunking together with the input limits of the models that use the chunks. The next experiment should preserve the question, control token budgets before indexing and generation, and evaluate the chosen settings on new questions and datasets. This would help determine whether semantic segmentation becomes competitive after the length mismatch is addressed. The current evidence supports overlap for retrieval in this compact pipeline, while leaving its advantage for exact answers uncertain.
