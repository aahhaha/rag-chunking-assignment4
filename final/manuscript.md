# Chunking and Context Limits in Retrieval Augmented Question Answering with Compact Models
Aibyn Samat
Astana IT University, Astana, Kazakhstan
Correspondence: 242187@astanait.edu.kz

## Abstract
Background: Document segmentation affects which evidence a retrieval augmented generation system represents, retrieves and passes to its answer generator. Meaningful boundaries may help, but variable fragment lengths can conflict with model input limits. Aim: This study compares fixed, overlapping and semantic segmentation in a compact English question answering pipeline. Methods: The same 500 questions from the SQuAD development set were evaluated with normalised MiniLM embeddings, exact FAISS search and greedy FLAN T5 base generation. Retrieval used five fragments, while generation received the first three. Binary outcomes were compared with exact paired McNemar tests and Holm correction. Uncertainty was estimated with 2,000 question bootstrap resamples. Results: Recall at five was 75.2% for fixed fragments, 81.8% for overlapping fragments and 66.4% for semantic fragments. Overlap improved retrieval over fixed by 6.6 percentage points, with a paired 95% interval of 3.0 to 10.0 points and adjusted p = 0.0008. Exact Match was 54.8%, 58.0% and 1.4%, respectively. The overlap advantage in Exact Match was not statistically established. Semantic prompts were truncated on 95.6% of questions. An exploratory context cap increased semantic Exact Match from 1.33% to 24.67% on the same 300 questions. Conclusion: Overlap improved retrieval in this configuration. Semantic boundaries alone did not compensate for incompatible input lengths. These findings support evaluating segmentation together with embedding and generation limits.

Keywords: evidence selection; passage segmentation; SQuAD; input truncation; paired evaluation

## 1 Introduction
Retrieval augmented generation connects a language model to a searchable collection of external text. The original RAG formulation combines parametric knowledge with retrieved passages to support knowledge intensive tasks {rag}. Dense passage retrieval provides an efficient route to candidate evidence {dpr}. A practical implementation must also decide the unit of retrieval. Whole articles usually contain too much unrelated material, whereas very short fragments may omit the sentence that explains an answer. Document segmentation therefore affects the information represented in the index before a user asks a question.

This study investigates that choice in a deliberately small pipeline. It uses public encyclopedic text and compact models that can run locally. The practical motivation is relevant to student projects and modest deployments where a larger context window cannot simply be purchased or assumed. A fragment that looks coherent to a reader may still exceed the text window used to construct its embedding. A later concatenation of retrieved fragments can also exceed the answer generator's input limit. The nominal presence of an answer in a retrieved string consequently differs from the availability of usable evidence to a model.

Two established components make this interaction measurable. Sentence embedding models map texts into comparable vectors {sbert}, while SQuAD supplies questions with human written answer spans in Wikipedia passages {squad}. The dataset enables separate checks of answer string retrieval and generated answer matching. These checks have limitations, especially when an answer string appears without its full supporting statement, but they are transparent and can be regenerated without a language model judge. That transparency is useful when interpreting a surprisingly weak result.

The comparison concerns three familiar segmentation choices: fixed character windows, the same windows with overlap, and semantic boundaries inferred from changes in sentence embeddings. Fixed windows offer a simple baseline. Overlap repeats a boundary region and can preserve text otherwise split between neighbours. Semantic segmentation aims to retain meaningful units, but its output length depends on the document. Qu and colleagues found no consistent advantage sufficient to justify semantic segmentation across their tested retrieval tasks {qu}. Kiss and colleagues reported benefits for their different Max Min algorithm {kiss}. These findings motivate a conditional comparison rather than an assumption that one family always wins.

Context handling provides a second reason to avoid universal rankings. Liu and colleagues demonstrated that models can use information differently depending on its position in long inputs {lost}. Their study concerns use of retained context, whereas the present pipeline also faces hard truncation. Automated RAG evaluation frameworks distinguish context relevance, answer relevance and faithfulness {ragas}. This distinction explains why a retrieval score should not stand in for answer quality. A method may retrieve the answer somewhere in a long fragment while the generator receives an incomplete prompt.

The research question is how fixed, overlapping and semantic segmentation change context availability and answer accuracy under the same compact model configuration. The original hypothesis predicts that semantic segmentation improves both Recall at five and Exact Match over fixed segmentation after correction for multiple comparisons. The study retains that joint rule even though its results favour other configurations. It treats the subsequent context cap and answer position checks as exploratory analyses, because they were added after a length problem became visible.

The contribution has three parts. First, the study supplies a paired comparison with identical question IDs, retriever, generator and scoring definitions, accompanied by question level outputs. Second, it connects the semantic condition's low answer score to observed prompt truncation and examines a matched context intervention without comparing unequal samples. Third, it provides a reproducibility record that separates an exact technical rerun from independent human replication. The contribution is an empirical comparison and diagnostic case, rather than a new segmentation algorithm or a state of the art claim. The following sections position the study in related work, specify the procedure, report the results, and discuss the conditions under which the conclusions apply.

## 2 Related Work
### 2.1 Retrieval representations and benchmark scope
Dense retrieval represents questions and passages separately, then ranks passages through vector similarity. Its effectiveness depends on the encoder as well as the definition of a passage. Broad embedding evaluations illustrate this dependence: MTEB compares multiple task types rather than assuming that success on sentence similarity guarantees success on retrieval {mteb}. The present work holds the encoder fixed. Its ranking of splitters therefore describes their compatibility with a particular encoder, rather than the best possible representation for every segmentation method.

BEIR further demonstrates the value of evaluating retrieval across heterogeneous domains {beir}. A result on encyclopedic questions cannot establish robustness for legal documents, academic theses or multilingual search. Our collection intentionally remains small and public so that each reported score can be traced to saved questions. This choice supports inspectability at the expense of external validity. It also means that a strong baseline from a broad retrieval benchmark should not be inferred from the local fixed window comparison.

Knowledge intensive benchmarks distinguish downstream task performance from supporting provenance. KILT explicitly evaluates both within a shared knowledge source {kilt}. Our hit indicator is simpler: it checks answer string containment in a fragment from the correct article. It does not identify every relevant passage or verify an entailment relation. The difference matters when comparing results with conventional information retrieval metrics. We retain the familiar Recall at k label but state its binary operational definition throughout the manuscript.

### 2.2 Segmentation and pipeline interaction
The closest direct comparison is Qu and colleagues' study of semantic and fixed segmentation across document retrieval, evidence retrieval and answer generation {qu}. Its main relevance is the absence of consistent semantic gains. Our work examines a narrower configuration with explicit character windows and compact local models. It cannot reproduce the authors' complete benchmark or their computation cost comparison. Its added evidence concerns a concrete mismatch between variable fragment length and the two models' input windows.

Kiss and colleagues' Max Min method forms consecutive sentence groups through semantic similarity {kiss}. Their clustering and multiple choice RAG evaluations differ from our percentile breakpoint implementation and open answer matching. A negative finding for our semantic condition consequently does not contradict every positive result in that paper. Table 1 compares the nearest studies by intervention and evaluation setting. The table makes explicit that algorithm names alone do not create equivalent experimental conditions.

Other RAG studies reinforce the need to examine interacting components. Upadhyay and Viviani combine topical relevance and factual accuracy in health information retrieval {health}. Elkiran and Rasheed compare retriever and reranker pairings using retrieval, generation and efficiency outcomes {pairings}. Both appear in the proposed primary journal. They establish a topical connection to pipeline evaluation, but neither supplies a directly comparable chunking effect. Our experiment does not measure health misinformation or reranking, and its saved timings cannot support their efficiency analysis.

Chen evaluates similarity measures in Chinese RAG using more than one dataset and encoder {chinese}. The study offers a useful contrast to our English, single encoder setting and reports paired statistical evaluation. Ghaywat and colleagues discuss conversational RAG as an architecture with interacting stages {survey}. Muthusami and Saritha combine retrieval and structured reasoning in an educational setting {hybrid}. These papers support the backup journal's topical fit. Their broader systems are context for this study rather than baselines implemented in our experiment.

### 2.3 Retrieved evidence and generated answers
Retrieval and generation can be coupled in different ways. Fusion in Decoder processes multiple passages through a model architecture designed to combine evidence {fid}. REPLUG augments a frozen black box model through a tunable retriever {replug}. Self RAG introduces adaptive retrieval and reflection during generation {selfrag}. These approaches establish that the effectiveness of external text depends on how a system selects and uses it. The present experiment uses simple concatenation and a fixed retrieval depth, so its results should not be transferred directly to architectures that integrate evidence differently.

The choice of generator also sets the scope. T5 expresses language tasks in a text to text format {t5}; instruction tuning improves the usability of released FLAN checkpoints {flan}. Using FLAN T5 base keeps local execution feasible but restricts the input budget compared with many contemporary models. We do not retrain or tune the generator for the three fragment distributions. This makes the local comparison controlled, while leaving the question of adaptation to longer passages unanswered.

Long context research distinguishes nominal window size from effective use. LongBench evaluates several long text tasks rather than relying on one question answering dataset {longbench}. Shi and colleagues show that irrelevant information can distract language models {distraction}. Together with positional effects {lost}, these studies caution against assuming that supplying more characters necessarily improves answers. Our recorded truncation is an additional, mechanically observable problem. We do not claim that positional sensitivity or distraction caused each error in our outputs.

### 2.4 Evaluation and the remaining gap
Surface matching offers a reproducible answer score, but it does not establish factual support. ARES evaluates context relevance, answer faithfulness and answer relevance using trained judges with human annotation support {ares}. ALCE evaluates the quality of evidence citations in generated text {alce}. These dimensions motivate future validation beyond EM and token F1. They were not measured here, and no unrecorded faithfulness score is inferred from answer matching.

Query representation is another possible intervention. HyDE generates a hypothetical document before retrieval {hyde}. We leave the query representation unchanged because the research question concerns segmentation. Adding query expansion, reranking or an adaptive retriever would introduce further moving parts and require a new evaluation. The remaining question addressed here is therefore specific: what happens when three off the shelf splitters are placed in the same compact pipeline, and how much of their observed difference can be interpreted alongside recorded length failures? This limited scope supports a clear diagnostic result without implying that the literature has never compared chunking before.

## 3 Materials and Methods
### 3.1 Design and provenance
The study uses a paired computational comparison. Each question is evaluated under all three conditions, and the dependent variables are retrieval hits, Exact Match, token F1, prompt truncation and retrieved character volume. The independent variable is segmentation strategy. The document collection, question IDs, normalisation, encoder, search index type, retrieval depth, prompt format and decoding settings are shared. Fragment lengths and index sizes vary as consequences of segmentation. Equal nominal settings therefore do not imply equal amounts of evidence actually processed.

The research develops the chunking question selected during the earlier course assignments. The main and context budget outputs were already produced for Assignment 3 and analysed further in Assignment 4. This manuscript integrates that work rather than presenting those runs as newly collected. The instructor permitted their reuse. The settings record is retrospective, and no pre experiment protocol upload is asserted. Recall at five was selected as the primary reporting outcome after the results were known; the original hypothesis still requires an improvement in both Recall at five and EM.

### 3.2 Dataset and sample
SQuAD version 1.1 development data contain 10,570 questions across 48 Wikipedia articles. Source paragraphs are joined within each article with two newline characters. All articles form the retrieval collection. A Python pseudorandom shuffle with seed 42 selects the first 500 questions. Every selected question has one or more reference answers, and all are retained. This is open retrieval within the development article collection, rather than the original reading comprehension setting that supplies a question's gold paragraph directly.

The exploratory budget run uses the first 300 questions of that same shuffled list. It is a subset, not a held out validation set. The pilot contains 100 questions and is reported separately. Saved question IDs allow exact alignment across methods and runs. The analysis asserts that all three methods contain the same IDs and that the budget IDs match the first 300 main IDs. SHA 256 hashes identify the source dataset, result files and experiment script. No new annotated dataset or model training split is created.

### 3.3 Segmentation and retrieval
Fixed segmentation uses LangChain CharacterTextSplitter with an empty separator, a 500 character chunk size and zero overlap. The overlap condition uses the same implementation and size with 50 overlapping characters. Semantic segmentation uses LangChain SemanticChunker with a percentile breakpoint threshold of 95. It compares sentence representations and splits at sufficiently large semantic changes. No maximum token cap is imposed on its output. The threshold is not a confidence probability or a target answer accuracy.

The encoder is sentence transformers all MiniLM L6 v2. Document and question embeddings are normalised. FAISS provides exact flat nearest neighbour search {faiss}. Five chunks are retrieved for each question. With unit vectors, squared Euclidean distance and cosine similarity induce the same ordering, apart from numerical ties. The experiment does not use an approximate index, a reranker or a learned query expansion stage. The maximum embedding sequence length is 256 tokens, with approximately 254 positions available for ordinary text after special tokens. Longer strings can be truncated during representation.

### 3.4 Generation and context intervention
The generator is google flan t5 base in evaluation mode. It receives the first three retrieved chunks concatenated with newline separators. The prompt requests an answer using only that context and places the question after it. Tokenisation uses truncation with a maximum input length of 512 tokens. Greedy decoding disables sampling and permits at most 32 new tokens. These settings are identical across segmentation conditions. They make the saved run deterministic in the observed environment, while not guaranteeing identical results under every software or hardware revision.

The intervention limits the concatenated context to its first 1,500 characters before prompt construction and tokenisation. Retrieval and the original index remain unchanged. This intervention responds to observed prompt overflow, and is exploratory. It can preserve space for the question, but also discards text within long fragments. It therefore tests a change in context construction, not an isolated change in semantic boundaries. The truncation indicator records whether the prompt exceeds the tokenizer's limit after any character cap. It does not report the exact token span lost in each question.

### 3.5 Metrics
A hit at k equals one when at least one of the first k chunks belongs to the question's article and contains a nonempty normalised reference answer string. Otherwise it equals zero. Recall at k is the mean of this indicator across questions, for k equal to one, three and five. This is answer string hit rate, not exhaustive recall over all relevant passages. It may accept an irrelevant occurrence of a short answer and does not establish that the generator receives the complete supporting statement.

Answer normalisation lowercases text, removes punctuation and English articles, and collapses whitespace. EM is one when the normalised prediction equals at least one normalised reference. Token F1 uses multiset word overlap to compute precision and recall, then their harmonic mean. For questions with multiple references, the best score is retained separately for EM and F1. Final answer scores average the per question values. Thus an acceptable shorter span may obtain zero EM and positive F1. The analysis does not use semantic similarity or an LLM judge to replace these definitions.

### 3.6 Statistical analysis
For each mean, the analysis samples question rows with replacement 2,000 times using bootstrap seed zero. The 2.5th and 97.5th percentiles define the 95% interval {efron}. Difference intervals use the same resampled question IDs for both methods. They estimate variability across questions conditional on this pipeline. The procedure does not simulate new model training runs. Questions from the same articles may be dependent, so the intervals should not be interpreted as fully accounting for document level uncertainty.

Binary Recall at five and EM outcomes are compared using exact two sided McNemar tests {mcnemar}. If b is the number of questions only method B answers successfully and a is the number only method A answers successfully, the test conditions on a plus b and evaluates a binomial null probability of one half. Holm adjustment controls multiple testing separately within the three Recall comparisons and within the three EM comparisons {holm}. The significance threshold is 0.05. F1 differences use paired bootstrap intervals because F1 is not binary. A nonsignificant result does not establish equivalence.

### 3.7 Error analysis ethics and reproducibility
All EM failures are grouped by the first matching rule: truncated prompt, no hit among five, hit only at ranks four or five, hit among three with F1 at least 0.5, hit among three with positive F1 below 0.5, or hit among three with zero F1. This priority prevents double counting. A separate qualitative review examines the first 30 fixed failures in saved order. AI assisted the labels, and the student reported checking them. No independent inter rater agreement is claimed.

The study analyses an existing public benchmark and recruits no participants or collects new personal records. The code and result outputs are provided with licensing information that distinguishes original analysis from third party data and models. A technical inference rerun on 27 October 2026 used the existing local environment and cached models. A separate clean environment check validated saved output analysis. These checks are described separately because installing analysis dependencies does not validate a clean model installation, and an AI operated rerun does not constitute external human replication.

### 4.2 Paired comparisons
Table 5 reports all six binary comparisons. For Recall at five, overlap succeeds alone on 58 questions and fixed succeeds alone on 25. The net gain is 33 questions, or 6.6 percentage points. Its paired bootstrap interval is 3.0 to 10.0 points, and its exact raw p value is approximately 0.000378. The Holm adjusted value is approximately 0.000757, reported as 0.0008. The overlap advantage is less conclusive for generation. Its EM exceeds fixed by 3.2 points, but the paired interval spans minus 1.0 to plus 7.0 points and the exact p value is 0.1332. This result supplies insufficient evidence for a difference at the chosen threshold. It does not show that the methods are equivalent. Both semantic EM comparisons are strongly negative. ### 4.5 Hypothesis and technical reproduction
The original semantic superiority hypothesis is not supported: semantic falls below fixed on both required outcomes. This conclusion refers to the tested percentile splitter and pipeline. On the later technical rerun, all 1,500 prediction strings and per item numeric metrics match the historical main outputs. Total elapsed time is 3,887.93 seconds. A clean saved output analysis also reproduces the main summary byte for byte, and six main McNemar values agree with SciPy. These checks establish technical consistency of the supplied evidence, while external human reproduction remains unperformed.

## 5 Discussion
### 5.1 Interpretation and comparison with prior work
Overlap improves the retrieval hit rate in this compact configuration. Repeating a short region can preserve answer text split by a fixed boundary, but it also changes representations and neighbour rankings. The saved CSVs do not retain ranked chunk IDs, so the 33 additional hits cannot all be attributed to repaired boundaries. The strongest supported conclusion is the paired improvement under the specified implementation. It remains possible that a token based or sentence aware baseline would behave differently.

The distinction between retrieval and generation explains the smaller answer improvement. Evaluation searches the first five fragments, whereas generation receives three. Even a hit among three only verifies containment before input truncation. The generator may choose a nearby wrong entity or provide an incomplete reference span. The EM and F1 intervals therefore add information beyond the retrieval result. They prevent an overstatement that a significant retrieval gain automatically produces a significant final accuracy gain.

The semantic result agrees with Qu and colleagues' caution about unreliable gains, but the evidence answers a narrower question {qu}. It does not quantify the computational cost of semantic segmentation. Nor does it invalidate Max Min, whose segmentation rule, evaluation tasks and models differ {kiss}. Pipeline studies in the target journal measure other interacting choices, such as relevance signals and reranking {health}{pairings}. Our contribution complements that approach by documenting the passage length problem rather than extending their numerical results to a different system.

The matched context check strengthens the interpretation that input construction mattered. The same semantic questions improve markedly after a cap, without rebuilding the retriever. However, the cap changes both retained evidence and the presence of the question within the final input. It is therefore a diagnostic intervention with several consequences. It cannot isolate a pure semantic boundary effect or establish an optimal 1,500 character budget. An independent evaluation would need to set that policy before examining new questions.

### 5.2 Practical implications
For an English encyclopedic application using these compact models, fixed windows with modest overlap are a reasonable configuration to evaluate first. The result is a starting point for a fresh application test, rather than a universal deployment recommendation. A developer should count tokens before indexing, preserve the question while packing context, and record the text that each model actually receives. Merely checking that a full retrieved string contains an answer can conceal losses at both the embedding and generation stages.

Long context benchmarks and positional studies explain why a larger window would not remove every difficulty {longbench}{lost}. Evidence can still be irrelevant or poorly used. Faithfulness frameworks also show why reference matching should be supplemented when an application needs grounded explanations {ares}{alce}. Our study establishes neither citation quality nor clinical reliability. It cannot rank methods by latency or price, because original per method timings were not recorded. Index count and retrieved character volume are insufficient substitutes for those measurements.

### 5.3 Threats to validity
Internal validity is limited by unequal effective input lengths, one setting per method and exploratory analyses selected after seeing outputs. A fair comparison of deployable configurations might allow separate token caps and parameter tuning, but that would ask a different question from placing the existing splitters into one fixed pipeline. The prompt's question at the end creates a particularly vulnerable input construction. The semantic score should consequently be understood as an implementation dependent failure case, not an intrinsic measure of semantic coherence.

Construct validity is limited by string containment and surface answer scoring. Short gold strings can occur in irrelevant contexts, and EM can penalise acceptable wording. The manual sample illustrates both issues but cannot estimate their population frequency. Statistical conclusion validity is limited by question dependence within 48 articles. Question bootstrap intervals may be narrower than an article cluster procedure would give. The analysis also uses separate correction families for retrieval and EM rather than correcting every exploratory analysis jointly. These choices are explicit so readers can judge their inferential scope.

External validity is limited to one English dataset, one encoder, one generator and a single question shuffle. The models may have encountered benchmark material during pretraining, so absolute answer accuracy cannot be interpreted as purely retrieval grounded reasoning. Greedy decoding does not remove dataset selection uncertainty. The full technical rerun uses cached models and the existing environment, and supplies no independent judgment of the qualitative labels. The instructor's acceptance of that arrangement concerns the course and does not change the scientific meaning of independent replication.

### 5.4 Follow up study
A stronger follow up should freeze the protocol before testing untouched questions, compare semantic segmentation with and without token caps, and align retrieval depth with generation budgets. It should include additional datasets and encoders, a strong lexical baseline, a no retrieval generator and a gold context condition. Those controls would help separate retrieval failure from generator limitations. Article cluster resampling and an external rerun would test robustness. Logging chunk IDs, embedding token counts, complete prompts, model revisions and per stage timings would make more precise explanations possible.

## 6 Conclusion
This study compared fixed, overlapping and percentile semantic segmentation in a compact RAG pipeline on the same 500 SQuAD questions. Overlap achieved Recall at five of 81.8%, compared with 75.2% for fixed and 66.4% for semantic. Its 6.6 percentage point retrieval advantage over fixed remained significant after Holm correction. The observed EM increase from 54.8% to 58.0% was not statistically established. The original hypothesis that semantic segmentation improves both retrieval and exact answers was not supported in this configuration.

The main diagnostic result is the separation between answer text retrieval and usable model input. Semantic prompts were truncated on 95.6% of questions and achieved 1.4% EM. On matched 300 question subsets, a context cap increased semantic EM from 1.33% to 24.67%. This exploratory result shows that context construction materially affected the observed performance, while leaving the pure effect of semantic boundaries unresolved.

The contribution is a traceable paired comparison with explicit metric definitions, a matched length intervention and a technical reproduction record. Its practical implication is to evaluate chunk boundaries together with the input limits of the models that consume them. Future experiments should preserve the question, control token budgets before indexing and generation, and validate the resulting configuration on untouched questions and additional datasets. These steps can test whether semantic methods become competitive after the identified length mismatch is addressed.
